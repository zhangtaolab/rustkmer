<objective>
Close gap **CR-03** (03-VERIFICATION.md gaps[0]): the streaming merge route — the default over-budget route, reachable directly from `PyDatabase.merge` — performs no cross-input k-mer-size/canonical validation. `merge_databases_streaming_to_path` (format.rs:1328) reads `kmer_size`/`canonical` from `read_header_of(input_paths[0])` only (format.rs:1348-1350); `ExternalMerger::sort_database` (streaming_merge.rs:263) validates nothing; `PyDatabase.merge` checks only existence/mode/budget. From Python, merging a k=21 DB with a k=31 DB under a streaming-selecting budget silently writes a corrupt database whose header claims input[0]'s k-mer size. The in-memory route rejects (format.rs:1545) and the prefix-cache route rejects k (format.rs:1687) — the streaming route is the outlier on the validation axis.

The fix: enforce cross-input compatibility in `merge_prologue` (format.rs:966) — the shared first statement of both public entry points — using the machinery that already exists (`read_header_of` + `validate_header_compatibility`), so all three routes and both front-ends (CLI and PyO3) inherit it with zero pyo3 changes.

Purpose: MERGE-01's correctness surface and MERGE-04's "same bounded path" promise — a route-dependent silent corruption class, the same class as the G3 gap the prior round closed.

Output: a merge prologue that rejects incompatible input sets on every route before any work starts, plus streaming-route rejection tests that are red on the current tree.
</objective>
