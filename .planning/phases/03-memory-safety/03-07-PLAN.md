<objective>
Close gap **G3** (= code-review finding CR-01) — the two merge routes silently disagree on any k-mer count above 1,000,000. `KmerEntry::read_from` (`src/database/format.rs:216-238`) applies an endianness heuristic — "if the little-endian read gives a count > 1,000,000, use the big-endian reading instead" — while `write_to` (`:210-213`) always emits `write_u32::<LittleEndian>`. Every count above 1,000,000 is therefore read back byte-swapped: the verifier reproduced `1_000_001 -> 1_094_848_256`, `2_000_000 -> 2_156_142_080`, `16_777_216 -> 1`.

Phase 3 made this newly load-bearing: `merge_databases` routes large merges to streaming, and the two routes apply the heuristic a different number of times. The in-memory route swaps once (`format.rs:328`); the streaming route swaps twice (`streaming_merge.rs:94` read, `:272` little-endian chunk write, `:314` read-back) and the double swap cancels by accident. The same input under the same budget therefore yields DIFFERENT DATA depending only on which route the budget picked.

Purpose: a merge that silently rewrites counts is silent data loss, and this phase unified both routes behind one `max_memory` / `merge_mode` API. The contract test for it already exists and is correct — it simply cannot reach the bug, because every fixture count is far below 1,000,000.

Output: an exact `write_to`/`read_from` pair with no heuristic, a threshold round-trip table that pins the previously-corrupted values, and a Rust route-parity test that exercises both routes on a fixture whose count exceeds 1,000,000.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.rkdb` bytes -> `KmerEntry` | Untrusted on-disk bytes are decoded into a count. A decoder that second-guesses the writer corrupts valid data. |
| merged chunk file -> streaming iterator | A chunk file written earlier in the same merge is read back; a damaged or truncated chunk is untrusted input. |
| budget selection -> route selection | `max_memory_usage` picks which of two implementations runs, and the output must not depend on that choice. |
