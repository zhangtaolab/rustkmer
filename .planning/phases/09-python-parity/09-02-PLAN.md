<objective>
Remove the `save_database` double sort and release the GIL around the save, while proving the emitted `.rkdb` bytes are unchanged and cross-surface identical to the CLI and the committed golden.

Purpose: `PyCounter.save_database` currently materializes the counter, performs a single-threaded stable `sort_by_key`, and hands `sorted=true` to `RKDatabase::from_kmer_pairs`, which sorts the same entries a second time. PY-01 requires one sort and a GIL release. The locked design sorts once with `rayon::par_sort_unstable_by_key` (the Phase 8 in-place pdqsort mandate) and writes through a NEW `format.rs` constructor that trusts the caller's order and marks the header `sorted: true` without sorting again. The whole save runs inside `py.detach` with owned `Send` captures (`String` path + cloned `Arc`).

The Phase 8 frozen-contract pin is a whole-file `git hash-object src/database/format.rs` equal to `eb0d5bf29330301930d98d801480cf73d1cf826a`. Adding the constructor necessarily changes that blob. No standing test or CI step pins the file hash — the pin lives only in the Phase 8 plan/evidence — so this plan re-scopes it explicitly: prove the change is a pure addition, re-run the byte-contract tests, record the new blob as the Phase 9 expectation, and keep every other Phase 8 pin (manifests/lockfile blobs, fixture manifest `f010e42a…`, writer-function behavior) in force. `from_kmer_pairs`, `DatabaseHeader::write_to`, and `KmerEntry::write_to/read_from` are not edited.

Output: a pure-addition sorted-input constructor with its own byte-equality test, a single-sort GIL-released `save_database`, a cross-surface byte-identity pytest, and the blob-audit evidence that supersedes the Phase 8 whole-file pin for `format.rs` only.
</objective>
