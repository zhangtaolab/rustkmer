<objective>
Cut the Python counting surface over to the one shared counting engine and land the D2 skip-N semantics on every Python counting input, without changing the public `PyCounter` API.

Purpose: `pyo3/src/counter.rs` is the last consumer still running its own sequential line loops and its own non-ACGT strip-and-join pre-filter. Phase 7 built `CountEngine` as the single counting entry point and Phase 8 proved its output bytes; Phase 9 is the structural cutover (PY-01) plus the ratified D2 semantics change (PY-02). This plan is the tracer: one Python call travels Python argument extraction -> `py.detach` -> per-call `CountEngine` -> `count_file` -> `finish` -> `CountResult::merge_into` -> observable `get_stats()` / `get_all_counts()` result, and the freshly rebuilt extension exports `__version__` so a stale `.so` cannot masquerade as the measured artifact.

The per-call engine shape is a locked decision: no engine is cached on `PyCounter`, `EngineConfig` gets `initial_capacity = 0` (the persistent counter already holds capacity), and the record format comes from the method name (`SequenceKind::Fasta` / `SequenceKind::Fastq`). `KmerCounter::new` accepts `_num_threads` and discards it, so `PyCounter` gains a private `threads: usize` field set from the already-resolved value in `new()` — invisible to Python.

D2 removes the non-ACGT pre-filter everywhere: the FASTA/FASTQ paths now feed raw bytes through `count_file`'s shared `for_each_window` extractor, and `add_sequence` feeds `seq_str.as_bytes()` directly. The user-visible consequence is recorded and tested: Python's nine-case total drops 70 -> 37 and 33 chimeric k-mers disappear (documented in 09-04). Whitespace and every non-ACGT byte now break windows in `add_sequence`; that is the locked scope, not an accident.

Output: engine-routed `PyCounter`, raw-byte D2 extraction, the five Wave-0 test gaps owned by this plan, rewritten pre-D2 parity tests with an anti-softening control, and a version-asserted rebuilt extension.
</objective>
