<objective>
Turn the proven controller spine into the production measurement path: a Python full-scale arm with the Phase-9 fresh-worker discipline, a mechanical Phase-10 renderer that carries every mandatory statement, and the slice-gate record that makes the parity reference's identity tamper-evident.

Purpose: Plan 10-01 proved the architecture on synthetic data. This plan makes the three remaining seams production-grade before any expensive run: the `py-t16` arm must validate the measured module and the resolved thread count on every rep, the report must state the descope and the measurement limitations as literal text (not prose that a future editor can quietly drop), and the slice-gate artifact must pin the committed reference's sha256 before consuming it — the Phase-9 review's `--previous` finding applied to this phase's own evidence.

The renderer is a NEW function in `phase10.py`. The v1.0 `render_report` and `test_render_report.py` are pinned byte-identically and are not touched. The report's only environment read is `harness_source_commit()`, which returns the last commit that touched the harness file and is therefore stable across re-renders.

`t1` reporting rule: the CLI session's t1 arm appears in the table and under a "scaling evidence" heading, never in a YES/NO computation. The Phase-10 report therefore cannot manufacture a NO the way the v1.0 `_count_verdict` would with a t1 arm present.

Output: production `py-t16` validation, the full mandatory-statement renderer, the slice-gate stage, their tests, and the README documentation of the stage/exit contract.
</objective>
