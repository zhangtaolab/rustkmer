<objective>
Build the Phase-10 measurement controller and close the two measurement gaps the verdict depends on — honest peak-memory accounting and a memory projection model — proving the whole mixed-tool spine end-to-end on synthetic data.

Purpose: the v1.0/v2.0 harness already owns the protocol primitives (counterbalanced rounds, discarded warmups, honest `cache_state`, provenance, parity gate, exit contract), but its full mode measures one part per arm, it has no Python arm, and it records only `maximum resident set size`. Phase 10's engineering is extension at four seams, and this plan builds the controller that owns them. The tracer task runs all four arms over TWO synthetic parts through one measured invocation each, so the both-parts seam, the Python worker seam, the rotation, the t1 exclusion, the verdict rule and the mechanical report are proven wired before any expensive run exists.

Tracer scope note: the tracer touches every layer this phase modifies — the harness parser (`bench.py`), the worker (`python_bench.py`), the controller and renderer (`phase10.py`), and the test module. The parser extension lands as the second task and the tracer's rep accessor is written forward-compatible so it reads `peak_bytes` when present and derives it from the recorded RSS otherwise.

`t1` is CLI-only scaling evidence: it runs in the same counterbalanced block, gets no separate warmup (the rustkmer warmup covers the tool), and is excluded from the acceptance rule by construction.

Output: `scripts/bench/phase10.py`, the `parse_time_output` extension, the repeatable-input worker, and the Wave-0 test files that carry the arm/verdict/report contract.
</objective>
