## Decisions Made

- Hardening `observe()` alone suffices; no stub behavior change. A `sample <pid> 1` window
  always spans ~1 s and the helper's final poll necessarily crosses the stub's exit, so no
  stub exit style can prevent a sampling window from crossing process death; a stub-only
  change would leave real counting children exposed to the same race.
- The peak over all nonzero observations is the honest steady-state measurement because a
  counting child's thread set is monotonically non-decreasing before exit and a truncated
  report can only under-count.
