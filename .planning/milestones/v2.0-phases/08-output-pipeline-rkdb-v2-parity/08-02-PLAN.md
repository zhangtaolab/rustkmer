<objective>
Prove `.rkdb` v2 byte-identity for the new counting output path and prove its sortedness through BOTH binary-search consumers.

Purpose: The goldens captured in Phase 5 are the contract; they are only re-hashed today, so a write-path drift would go unnoticed. This plan turns them into a real old-vs-new differential: the same literal input is counted by the new engine, written by the new sort/stream path, and compared byte-for-byte against the committed pre-refactor fixtures, against the frozen canonical writer, and against a hand-built byte reference. Sortedness is then proven the way v1.0's CR-02 precedent demands — by asking `DatabaseQuery` and the prefix query and checking their answers — never by trusting the header flag.

Output: `tests/rkdb_v2_byte_identity_tests.rs`, with fixture integrity, four-arm byte equality on the six sorted cells, content equality on the six unsorted cells, header-literal assertions, and both-consumer answer parity.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed golden fixtures -> byte-identity claim | a regenerated fixture would make any drift pass |
| on-disk record order -> binary-search consumers | a lying sorted flag produces silently wrong answers |
| header literals -> readers | a drifted flag or offset corrupts every consumer |
| differential arms -> proof independence | arms sharing the code under test cannot detect its defect |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-06 | Repudiation | golden fixtures regenerated to pass | high | mitigate | Manifest sha256 pinned to f010e42a in the test; all 12 fixtures hashed against it; `git status --porcelain -- tests/fixtures/` must be empty; no generator is invoked |
| T-08-07 | Tampering | header literals or IN-03 meaning drift | high | mitigate | Full 42-byte header assertions (magic, version, kmer_size, flags, offsets) plus record-count vs sum-of-counts asserted on data where they differ; `format.rs` blob hash pinned in 08-04 |
| T-08-08 | Integrity | sorted flag claims order that does not hold | high | mitigate | Both consumers answer oracle queries (disk + preload binary search, prefix with exact block bounds); unsorted disk query must error; strict ascending assertion on disk keys |
| T-08-09 | Spoofing | differential arm shares the code under test | high | mitigate | Four independent arms: new CLI path, committed fixture (pre-refactor bytes), frozen canonical writer, hand-built record bytes from the oracle |
| T-08-10 | DoS | test runtime/memory | low | accept | Fixtures are a few thousand distinct keys; a 20k-base consumer fixture; no large files are materialized |
| T-08-SC | Tampering | cargo dependency set | high | mitigate | No new dependencies; `--locked` test runs; manifests/lockfiles verified unchanged in 08-04 |
</threat_model>
