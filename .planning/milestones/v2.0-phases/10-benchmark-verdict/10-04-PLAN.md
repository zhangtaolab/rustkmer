<objective>
Measure the Python surface at full human scale, prove all four arms counted the same bytes, compute the milestone's acceptance verdict from the recorded medians, and render the mechanical report — this is Checkpoint 2.

Purpose: Plan 10-03 produced the CLI evidence and stopped at Checkpoint 1. This plan first converts the measured CLI distinct counts into a hard Python memory decision, then runs the two Python sessions (jellyfish + `pyrustkmer`, both parts, 16 threads, three counterbalanced reps), then computes the verdict and renders the report. The preflight is a gate, not an estimate to "try anyway": the Phase-9-measured single-call cost is 86 B per distinct k-mer, and the two-call union model can climb toward an OOM cliff around 1.4-1.6 B distinct. At the research point estimate the projection is about 80-95 GB against a 110 GiB budget, so the decision must be re-derived from the measured count, never copied from an estimate.

Per-surface rule: each surface's verdict uses the jellyfish median recorded in the SAME counterbalanced session, so `rk-t16` is compared against the CLI session's `jf-t16` and `py-t16` against the Python session's `jf-t16`. The two jellyfish medians are reported side by side, and the cross-session count/fingerprint identity check proves both sessions counted the same input.

Checkpoint 2 is the phase's deliverable: the verdict artifact, the rendered report, and the plain statement of the measured outcome. A NO is a valid answer to the milestone's acceptance question; the phase never tunes anything to change it.

Output: `10-python-preflight.json`, `10-results-python-k21.json`, `10-results-python-k31.json`, `10-verdict.json`, `10-BENCHMARK-REPORT.md`.
</objective>
