<objective>
Expand the proven sequential tracer into the phase's real engine: one producer on the caller thread, N persistent OS workers with disjoint partition ownership, bounded per-worker queues with backpressure, a file-boundary flush/ack protocol, and a checked end reduction. Cut the CLI fully over to the engine and update the PROF-02 gate to the engine's exact thread model without softening it.

Purpose: Recover the measured ~3.5x parallel-scaling deficit by removing the per-chunk fork-join barrier and shared-table contention. This plan is where ENGINE-01's worker pipeline and the 2N+1 pool-size contract land.

Output: `src/count/batch.rs`, the parallel `CountEngine`, a CLI with no legacy counting loop, the updated PROF-02 observer/gate with a RED negative control, and exactness/robustness tests including multi-member gzip and worker-error paths.
</objective>

    In `src/count/engine.rs`, keep the 07-01 sequential path for `config.threads == 1` byte-for-byte. For `threads > 1`, `CountEngine::new` must spawn exactly `threads` persistent OS threads with `std::thread::Builder::new().name(format!("rustkmer-count-{i}"))`, each owning the `Vec<LocalKmerCounts>` for its contiguous `PartitionLayout::worker_range(i)` (capacity `max(initial_capacity / partitions, 1)` per table) and never touching another worker's tables. Create one `std::sync::mpsc::sync_channel::<CountBatch>(queue_batches)` per worker for batches and one `sync_channel::<WorkerStat>(1)` per worker for acks; move the receiver and ack sender into the worker closure. The worker loop receives batches until all senders drop, increments the owned table for each key (`Dense` keys as u64 widened to u128, `Wide` keys as u128) with no shared state, answers `Flush { token }` with `WorkerStat::Flush { token, total, unique }` summed over its tables with `checked_add`, and finally returns `ProcessingResult<Vec<LocalKmerCounts>>`. Workers never call rayon, never print, and never `unwrap`.

    The producer (the caller thread) must reuse the ONE `for_each_window` sink: for k <= 32 accumulate `u64` keys into the per-partition `Vec<u64>` buffer, for k > 32 accumulate `u128` keys; when a buffer reaches `keys_per_batch`, `send` a `CountBatch` for that partition (the send moves the Vec and blocks on a full queue, providing bounded backpressure). At the end of each file, flush every non-empty buffer, send `Flush { token }` to every worker, and collect one ack per worker; reject a stale token, and sum ack totals/uniques with `checked_add` using the 07-01 verbatim messages. Return cumulative `FileStats` with `skipped_batches` from the producer's records-per-warning-batch accounting. `stats()` returns the last flushed cumulative stats. `flush()` performs the same file-boundary barrier without reading a file.

    Error and shutdown contract: on any `send` error, any ack `recv` error, or any worker-returned error, stop producing, drop every sender (including queued flush senders), join every worker, and return a `ProcessingError` carrying the worker/queue context. A shared `AtomicBool` stop flag may be used but workers must still drain/exit on sender disconnection. `finish(self)` drops all senders, joins every worker, propagates the first worker error, concatenates the workers' table Vecs in layout order, and returns `CountResult` with checked aggregate stats. `Drop` drops senders and joins surviving threads, ignoring errors; no thread may leak and no panic may cross a worker boundary (`panic = "abort"` in release makes a worker panic fatal, so the worker path must be panic-free). Add `pub fn worker_count(&self) -> usize` returning 0 for the sequential path and `threads` for the parallel path.

    Add direct-engine integration tests: `engine_worker_pipeline_is_exact_at_t1_t4_and_t16` calling `CountEngine` with threads 1, 4, and 16 on the same multi-record fixture and asserting identical maps, totals, uniques, and skipped counts; `engine_worker_count_matches_requested_threads`; `engine_layout_handles_non_divisible_worker_counts` (threads 3 and 5 with P=64 assert every partition is owned exactly once and every worker count is as requested); and `engine_multi_file_cumulative_is_exact_with_workers` (two files, cumulative == elementwise sum).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| producer thread -> per-worker queues | Owned key batches cross a thread boundary; backpressure and disconnect semantics decide liveness |
| worker threads -> partition tables | Each key must have exactly one owner; any sharing would race or duplicate counts |
| CLI child process -> pool-size observer | The gate's honesty depends on observing the real OS thread total |
| compressed input -> decompressor -> parser | Multi-member and trailing-garbage behavior must stay loud and complete |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-06 | Tampering | Worker -> partition increment | high | mitigate | One owner per key via `partition_of`; tables moved into workers; no shared mutable state during counting; t1/t4/t16 exact-map and proptest conservation tests |
| T-07-07 | DoS | Bounded queue + flush/ack + error path | high | mitigate | Per-worker queues and acks; every send/recv/disconnect treated as worker failure; stop producing, drop senders, join all threads on every error; `Drop` joins; overflow and Drop tests with watchdog deadlines |
| T-07-08 | DoS | Worker panic under `panic = "abort"` | medium | mitigate | Workers return `ProcessingResult`, no `unwrap`, checked arithmetic, no unchecked indexing; invariants validated at construction with `debug_assert` only |
| T-07-09 | Tampering | Partition ownership / key leakage | high | mitigate | Pure `partition_of`; layout unit tests prove exactly-once ownership; sum of per-table unique/total equals global; union equals reference |
| T-07-10 | Repudiation | PROF-02 pool-size gate | high | mitigate | Exact 2N+1 / 2 formula; polling to the expected total; end-to-end RED negative control against the pre-engine N+1 stub; no `>=`, no override, no self-report |

| T-07-SC | Tampering | Cargo dependency set | high | mitigate | No new dependencies; every build/test uses `--locked`; `Cargo.toml`/`Cargo.lock` unchanged |
