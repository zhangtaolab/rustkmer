<objective>
Close the single remaining gap of 03-VERIFICATION.md round 3 (gaps[0], truth 10's streaming-writer arm): the mixed-canonical prefix-cache capability is still broken when the per-bucket STREAMING writer runs — `merge_mode='streaming'` (a documented MergeConfig field and CLI `--merge-mode` flag) or `auto` for any bucket over the per-bucket threshold. The verifier reproduced it in-repo through the public API on the 03-16 fixture: key 0 emitted twice, non-ascending output under header `sorted: true`, `query_kmer` returning Some(5) where the oracle is Some(8). Root cause: `merge_single_prefix_streaming` (src/database/prefix_cache_merge.rs:814-971) is a k-way BinaryHeap merge assuming every shard is an ascending run, but post-03-16 `split_files_by_prefix` stores the CANONICALIZED key while appending records in raw-key stream order — a non-canonical input's shard in a mixed set need not be ascending.

Fix choice (weighed against the three options in gaps[0].missing[0]): implement **option (a)** — in `ExternalSortMerger::new`, when the folded canonical mode is true and any input header is non-canonical, force the sorting (hashmap) per-bucket writer for all buckets and log the override. It is the verifier-suggested smallest safe fix, single-site, and the only option that keeps a `merge_mode='streaming'` merge SUCCEEDING (correctly, via the override) instead of erroring or corrupting. Option (c) (sort each shard pre-read) was rejected: it doubles phase-1 IO and adds a sort pass whose worst-case per-shard footprint is no better than the hashmap writer it would substitute. Additionally implement **option (b)** as the refusal backstop inside `merge_single_prefix_streaming`: validate per-file runs at record consumption and fail loudly on the first adjacent descending pair. Header flags are claims, not verified properties, so (a) alone cannot cover every writer-breaking configuration (an unsorted or mislabeled input of ANY canonical mode still feeds non-ascending runs to this writer — the same silent-corruption class under the same truth); (b) converts all of it into a loud WR-04-preserving merge failure. Together they discharge the "make the guarantee hold for EVERY writer, or refuse configurations that break it" commission: hold by forced construction where detectable, refuse loudly where not.

Also per gaps[0].missing[2]: correct the two known-false comments (the meet-and-sum sentence in prefix_cache_merge.rs :294-307 and the helper comment in tests/prefix_cache_output_order_tests.rs :94-96). Per missing[1]: extend the mixed-canonical e2e test with the `merge_mode='streaming'` arm.
