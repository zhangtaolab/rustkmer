<objective>
Fix the merge estimator's OOM-on-estimate bug and add hard admission control (D-01, D-02).

Purpose: MERGE-01 ("human-scale merges no longer OOM") and MERGE-02 ("estimate required memory, route to streaming when budget exceeded") are blocked by a single load-bearing bug: `should_use_streaming` and `merge_databases` both call `RKDatabase::from_file_path(path)` per input just to read `total_kmers` — which materializes EVERY entry into RAM during the estimate, OOMing the process before the merge strategy is even chosen (per 03-CONTEXT.md D-01, verified at `src/database/format.rs:644-652` and `:692-708`). This plan replaces those calls with a header-only `DatabaseHeader::read_from` (42 bytes, no entries) + a `file_size / 20` fallback, and adds the D-02 reject path so an explicit `--merge-mode memory` over-budget request errors instead of silently OOMing.

Output: A bounded merge dispatcher where the estimator reads only headers, the streaming path is hard-selected when the estimate exceeds budget, and the in-memory path is retained behind explicit `--merge-mode memory` (rejecting when over budget) for small/test merges and `--merge-mode auto` (small-input fast path).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.rkdb` file on disk → estimator | An untrusted/corrupt `.rkdb` path crosses into the estimator. `DatabaseHeader::read_from` validates magic + version before any field is trusted (Phase 1 hardening); the D-01 fix reuses this validation rather than bypassing it. |
| CLI `--max-memory` string → MergeConfig.max_memory_usage | `parse_memory_size` (merge.rs) validates the user string before it reaches the estimator comparison. Unchanged by this plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `estimate_total_kmers` (D-01 header read) | medium | mitigate | Reuse `DatabaseHeader::read_from` which validates magic bytes + version before trusting `total_kmers` (ASVS V5 input validation). A corrupt/tampered header returns Err, not silent garbage. The `file_size / 20` fallback is a coarse upper bound — safe because it only over-estimates and routes to streaming conservatively. |
| T-03-02 | Denial of Service | `merge_databases` estimator (the pre-D-01 OOM-on-estimate bug) | high | mitigate | This plan IS the mitigation: removing the `from_file_path` call eliminates the OOM vector. Post-fix, a malicious huge `.rkdb` cannot OOM the estimator because only 42 bytes are read. Covered by `merge_over_budget_hard_routes_to_streaming` + `estimator_reads_header_only_no_materialization`. |
| T-03-03 | Information Disclosure | D-02 reject-path error message | low | accept | The Err message includes byte counts (estimate, budget) — not sensitive data (local CLI, user-supplied budget). Acceptable for ASVS L1; matches existing anyhow error verbosity. |
