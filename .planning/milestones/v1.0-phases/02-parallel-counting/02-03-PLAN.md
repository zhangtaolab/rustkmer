<objective>
Expose the parallel counting speedup to Python by adding a `threads` kwarg to `PyCounter` and releasing the GIL around the heavy counting methods via `pyo3::allow_threads` (D-08). This delivers PCOUNT-03 — the shared core (DashMap from 02-02) flows to Python automatically once the GIL is released.

Purpose: Without GIL release, rayon workers would hold the GIL and execute serially — no parallel speedup regardless of how many threads the pool has. The `threads` kwarg gives Python users the same control the CLI's `--threads` flag gives (parity per D-08). This is the binding-layer change that makes the Phase 2 perf win reach the `pyrustkmer` surface.

Output: `PyCounter(k, canonical, initial_capacity=N, threads=M)` constructor; `Arc<RustPyCounter>` internal field; `add_from_fastq`/`add_from_fasta` wrapped in `py.allow_threads`; `add_kmer`/`add_sequence` left holding the GIL (sub-millisecond, not worth the release overhead — RESEARCH Open Question 1).
</objective>
