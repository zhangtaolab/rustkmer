Fill in the differential correctness tests scaffolded by 02-04 and extend pyo3/tests/test_counter.py for the PyCounter threads kwarg. This plan is the PCOUNT-04 gate: it proves (a) parallel counting produces results identical to sequential (the commutativity differential), (b) post-refactor counts match the committed pre-refactor baselines (D-10), (c) output is deterministic run-to-run (D-09), (d) the thread-resolution precedence chain works (PCOUNT-01), and (e) PyCounter inherits the parallel speedup with identical counts (PCOUNT-03).

Purpose: This is the high-signal bug detector for the whole phase. Because k-mer counting is integer addition (commutative + associative), ANY divergence between `--threads 1` and `--threads N` is, by construction, a concurrency bug (lost update or double count) — never benign ordering. Combined with the committed baseline assertion, this gives a definitive yes/no answer to "did the dashmap swap break correctness?"
