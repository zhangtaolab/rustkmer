<objective>
Capture the PRE-refactor sequential count MAPS as committed JSON baselines BEFORE the dashmap swap in 02-02 touches `src/hash/table.rs`. This is the D-10 golden-capture-before-refactor discipline (mirrors Phase 1's D-10 sequencing) and is the foundation the 02-05 differential test will assert against.

Purpose: k-mer counting is integer addition (commutative + associative), so the final count per k-mer is mathematically independent of threading. That makes a 1-vs-N count-map differential a high-signal, zero-noise concurrency-bug detector — BUT only if there is a stable, committed baseline captured from the CURRENT sequential code. This plan captures that baseline as JSON count maps (order-independent, so sharded DashMap iteration order in the refactored code cannot create false failures — Pitfall 5). It also scaffolds the `tests/parallel_count_tests.rs` binary so 02-02 and 02-05 can drop their assertions into a compiling harness.

Output: Committed `tests/fixtures/parallel_count_baseline/*.json` (>=6 files, D-13 matrix) + `tests/parallel_count_tests.rs` test binary skeleton (capture generator #[ignore]d + differential stubs).
</objective>
