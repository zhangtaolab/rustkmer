Using `allow_threads` would have FAILED the `-D warnings` FOUND-01 gate. | advisory | For ANY pyo3 GIL-release work on the 0.27.x pin: use `py.detach(..)`, not `allow_threads`. Don't trust second-hand API-version claims — grep the installed `marker.rs` for the `#[deprecated]` attribute. The shipped `pyo3/src/counter.rs` already uses `detach` correctly. |
| Logic-correctness fixes verified by compile/test only | Pass-1 WR-02/WR-03 (merge-overflow stats; `total_kmers` increment timing) and pass-2 WR-01 (the `total_kmers` denominator shift that WR-03 induced in `FilteringResult::kept_percentage`) were auto-fixed. | Re-review after fixes surfaces adjacent bugs | Pass 1 fixed the cited warnings but the fix surface had MORE unfixed instances of the same bug class (e.g. `fasta.rs::count_sequences`/`total_sequence_length` still used plain `File::open` after WR-01 fixed `validate_fasta_file`), and one fix induced a new semantic issue (WR-03 → denominator shift). The `--auto` flag automates this fix→re-review loop (capped at 3). |
